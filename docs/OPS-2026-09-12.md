### 1. MinIO 临时对象存储上线（对话工作台上传功能修复）

**背景**：lobehub 的 S3 原为跳过启动校验的假配置（`https://s3.local`），任何文件上传均 DNS 解析失败。

**部署**（全部在服务器侧，主 compose 未改动）：
- 容器 `minio`：API `127.0.0.1:9000`、Console `127.0.0.1:9001`，卷 `playground_minio_data`，网络 `playground`
- 配置写入 `/opt/playground/docker-compose.override.yml`（新增 minio 服务 + lobehub 的 S3 env 与 `extra_hosts`）
- 凭证写入 `/opt/playground/.env`（`MINIO_ROOT_USER=lobe-admin`；S3 专用账号 `lobe-uploader`）
- Bucket `lobe-temp`：匿名 download 可读；账号策略 `lobe-temp-rw`（仅限该桶）；**ILM 生命周期规则 2 天自动过期**（rule `dai1pft1dnls7cht836g`）
- lobehub env：`S3_ENDPOINT=https://s3.ai.1canc.com`、`S3_PUBLIC_DOMAIN` 同、`S3_BUCKET=lobe-temp`、`S3_ENABLE_PATH_STYLE=1`、`S3_SET_ACL=`（空）、`extra_hosts: s3.ai.1canc.com → 172.20.0.1`（容器走宿主机 nginx）

**排障过程（三个关键坑，务必留档）**：

1. **`S3_ENABLE_PATH_STYLE` 必须写 `1`**
   lobe 源码判断为 `process.env.S3_ENABLE_PATH_STYLE === '1'`，写 `true` 会被判为 false，
   SDK 将走 virtual-host 风格（`bucket.s3.domain`）导致证书不匹配/404。

2. **宝塔全局 `proxy.conf` 的 `proxy_cache cache_one` 会把 HEAD 改写成 GET**
   宝塔 `/www/server/nginx/conf/proxy.conf` 含 `proxy_cache cache_one;`（http 级生效），
   配合 nginx 默认 `proxy_cache_convert_head on` → 经反代的 **HEAD 请求被改写为 GET 发往上游**，
   S3 预签名（按 HEAD 签名）校验必然失败（403），导致 lobe 上传流程的 `HeadObject` 预检查中断。
   **修复**：在 `s3.ai.1canc.com.conf` 的 location 内追加
   `proxy_cache off;` 与 `proxy_cache_convert_head off;`（改前备份 `*.bak-minio-fix-20260911-234114`，`nginx -t` 后平滑 reload）。

3. **`S3_SET_ACL` 保持空（false）**
   MinIO 不支持对象 ACL 头；文件预览由 lobe 走 2 小时期预签名 URL（`getFullFileUrl` 行为）。

**验证（端到端，浏览器真实上传）**：`HEAD(404 预检) → OPTIONS 204 → PUT 200 → HEAD 200 → GET 200` 全链路通过；
对象落盘 `lobe-temp/files/496984/fb0c406a-*.txt`；非法/过期签名与匿名 PUT 均正确拒绝（403）。

## 附：对话工作台性能优化专项（09-12 凌晨，A+B+D）

**背景**：对话工作台（lobe）加载慢、切换路由后整页重载。

**实测（优化前，真实浏览器 + 本地网络）**：
- 首屏 DOMContentLoaded **17.9s**（250 请求 / 4.06MB gzip 后）
- **二次访问 5.3s，仍传输 3.44MB（250 请求仅 11 个命中缓存）** ← 核心问题
- 服务端无瓶颈：TTFB 164ms、容器空闲、出口 ~19Mbps；实测用户下载 251-472KB/s（~2-3.8Mbps）
- 服务器侧 BBR / HTTP/3(QUIC) / gzip / gzip_proxied 均已启用

**根因**：
1. lobe（Next.js public 目录）静态资源 `Cache-Control: public, max-age=0` → 每次访问重复下载、无强缓存
2. 首屏 4MB / 250 请求 在 ~2Mbps 链路上理论下限即 16s
3. 壳页面路由切换销毁 iframe → 第三方应用（lobe）整页重载

**已实施优化**：
- **A. 静态资源长缓存**：`chat.ai.1canc.com.conf` 新增 `location ^~ /_spa/assets/`
  （`proxy_hide_header Cache-Control/ETag` + `add_header Cache-Control "public, max-age=31536000, immutable"` + `gzip_proxied any`）
  备份：`/root/perf-backup/chat.ai.1canc.com.conf.bak-20260912-003626`
- **B. 工作台 iframe 保活（keep-alive）**：`frontend/src/App.vue` 的 RouterView 改为
  `<KeepAlive :include="['PlaygroundView']">` + `<component :key="route.fullPath">`；
  `PlaygroundView.vue` 增加 `defineOptions({ name: 'PlaygroundView' })` 与 `onActivated` 幂等重注入
  （管理后台配置变更后，切回时自动重新注入）。
  提交 `aa744557f`；镜像 `sub2api:perf-20260912`（新入口 `assets/index-CFqgCMsf.js`）
- **D. gzip 压缩级别**：全局 `gzip_comp_level 2 → 6`（备份 `/root/perf-backup/nginx.conf.bak-20260912-003626`）；
  Brotli 因服务器 nginx 未编译该模块，**跳过**（如需可后续用宝塔插件方案）
