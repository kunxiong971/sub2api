## 一、生图台/画布"生成失败"根因与修复（本日核心）

### 现象与排查过程

- 现象：浏览器端生图全部显示"失败"，但服务器侧所有请求均为 200（含完整 b64 图片响应）
- 逐一排除：上游可用性（直连 200）、账号配置（正常）、前端超时（默认 600s）、监控探活（已单独修复）
- **最终定位**（真实浏览器 F12 控制台实锤）：
  ```
  CORS policy: The 'Access-Control-Allow-Origin' header contains multiple
  values 'https://draw.ai.1canc.com, *, *', but only one is allowed
  ```

### 根因：/pgw 响应 CORS 头三层叠加

| 层 | 来源 | 值 |
|---|---|---|
| ① | nginx `/v1/` 配置 | `*`（pgw 反代走**公网域名**绕回 nginx，被套进来）|
| ② | pgw 服务 PGWCORS 中间件（fork 二开）| 回显 origin |
| ③ | nginx `/pgw/` 配置（09-12 修预检时加）| `*` |

浏览器规定该头只能有一个值 → 多值直接拒绝 → 前端"失败"。
**与账号的「透传」等模式设置无关**（透传不影响响应头）。

### 修复（已上线并验证）

1. nginx `/pgw/` 增加 `proxy_hide_header Access-Control-Allow-Origin/Methods/Headers`，隐藏上游重复头，只保留 nginx 唯一一个
   - 备份：`/root/perf-backup/ai.1canc.com.conf.bak-cors-fix-20260914`
2. 配套修复：
   - `PlaygroundView.vue`：生图台/画布优先激活含图片模型的分组（此前默认激活纯文本组，模型列表里无图片模型）→ 镜像 `wb-fix-20260914`
   - 账号 1 开启 `images_url_to_b64_json`（图片内嵌返回，不再依赖外部图片域名，保底措施）
3. **验证**：真实浏览器（playwright）完整复现用户操作：4K 16:9 + gpt-image-2.5-sunburst → **出图成功** ✅
