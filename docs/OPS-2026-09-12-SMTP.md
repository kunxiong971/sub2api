## 二、部署摘要（已回退，仅留档）

1. **Postfix**：587 submission（强制 TLS + SASL PLAIN/LOGIN，cyrus auxprop `no-reply@1canc.com`），`mynetworks=127.0.0.0/8, 172.19.0.0/16`（sub2api 容器网段），25 端口公网入站不放行
2. **TLS 证书**：复用宝塔 `ai.1canc.com` 证书拷贝至 `/etc/postfix/tls/`——sub2api 的 Go SMTP 客户端走系统信任链校验（`ServerName=host`），证书域名与连接主机名一致即可，无需 mail 子域单独签证书；容器内经公网 IP 回环直连宿主机，**compose 零改动**
3. **OpenDKIM**：`d=1canc.com, s=mail`，socket `/var/spool/postfix/opendkim/opendkim.sock`
4. **ufw**：`allow from 172.19.0.0/16 to any port 587`
5. sub2api 侧：settings 表写入 7 个 `smtp_*` 键 + `docker restart sub2api`

### 排障坑（留档）
- **OpenDKIM socket 权限**：默认 socket 组为 opendkim，postfix smtpd 无权连接（`Permission denied`，邮件未签名静默发出）。解法：`opendkim.conf` 的 `UserID` 设为 `opendkim:postfix` + 目录 `chown opendkim:postfix` + `UMask 007`；注意 **chroot 服务与非 chroot 服务的 milter socket 路径解析不同**（chroot 相对 `/var/spool/postfix`，非 chroot 用绝对路径，master.cf submission 内 `-o smtpd_milters=` 单独覆盖）
- **Go PlainAuth 必须有 AUTH 扩展**：Postfix 不 advertise AUTH 时 `client.Auth()` 直接报错，因此 587 必须启用 SASL（本次用 cyrus auxprop/sasldb，免装 dovecot）
- **测试脚本连 `127.0.0.1` 会因证书 IP不匹配失败**——用域名（ai.1canc.com）连接即正常，属测试方法问题非服务问题

## 四、163 邮箱接入（当前方案）

后台「系统设置 → 邮件（SMTP）」填写（**已配置 163 并验证连通 ✅**）：

| 配置项 | 值 |
|---|---|
| SMTP 服务器 | `smtp.163.com` |
| 端口 | `465`（客户端 `use_tls=true` 走隐式 TLS；填 25/994 亦可，客户端会自动 STARTTLS） |
| 用户名 | 完整 163 邮箱地址 |
| 密码 | **授权码**（163 邮箱设置 → POP3/SMTP/IMAP 开启服务后生成，非登录密码） |
|发件人 | **必须与用户名一致的 163 地址**（否则 163 会拒信/判垃圾） |
| 发件人名称 | Sub2API |
| 使用 TLS | 是 |

保存后用后台「测试连接/发送测试邮件」验证。注意事项：
- 163 对发信频率与内容有限制，验证码类邮件正常量级无碍；若被拒（554 DT:SPM 类错误码）多为内容/From 不匹配
- 若将来量大或需要自有域名发信（`no-reply@1canc.com`），可参考本文档第二节重启自建方案，或改用第三方（Resend/阿里云邮件推送等）
